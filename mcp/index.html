Upscaler expose une seule table d’outils, utilisée de deux façons : l’objet window.BinksyAPI (toujours présent dans app.html) et, si le navigateur le permet, des outils WebMCP enregistrés automatiquement. Chaque outil appelle la même logique que l’interface : l’écran se met à jour et l’enregistrement automatique suit. Toutes les méthodes sont asynchrones, renvoient du JSON et, en cas d’erreur, rejettent avec { code, message }.

Les modèles d’IA tournent dans le navigateur (ONNX Runtime Web) : prévois des délais longs sur processeur, et une connexion Internet pour télécharger le moteur et, au premier usage, chaque modèle. bicubic et nearest marchent sans moteur.

01Ce que l’agent peut faire

12 outils, aussi listés par await BinksyAPI.describe() avec leurs schémas JSON :

  • upscaler_describe · BinksyAPI.describe() — Décrit Upscaler (agrandissement d'images par IA dans le navigateur, jusqu'à ×8) et liste ses outils avec leurs schémas JSON.
  • upscaler_get_state · BinksyAPI.getState() — État courant : images importées (id, taille, dernier résultat), image courante, réglages (modèle, facteur, retouches, export) et état du moteur IA.
  • upscaler_importer · BinksyAPI.importer() — Importe les images de l'utilisateur (PNG, JPEG, WebP…), comme un glisser-déposer.
  • upscaler_lister_modeles · BinksyAPI.listerModeles() — Liste les 18 modèles (16 IA + bicubic + nearest) : id, nom, famille, facteur natif, poids, licence (commercial ou non), usage conseillé, déjà téléchargé ou non.
  • upscaler_choisir_modele · BinksyAPI.choisirModele() — Choisit le modèle (comme un clic sur sa carte).
  • upscaler_regler · BinksyAPI.regler() — Règle l'agrandissement et l'export : factor (2, 3, 4, 8) ou width (largeur précise 16–32 000 px ; 0 = facteur), denoise, mix (force de l'IA), sharp, grain (0–100), alpha (ai, fast), ep (auto, webgpu, wasm), tile (0, 64, 128, 256, 384), fmt (png, jpeg, webp), qual (50–100), dpi (72, 150, 300).
  • upscaler_agrandir · BinksyAPI.agrandir() — Lance l'agrandissement avec le modèle et le facteur courants et attend la fin (plusieurs minutes possibles sur processeur ; le premier usage d'un modèle IA le télécharge).
  • upscaler_annuler_calcul · BinksyAPI.annulerCalcul() — Annule l'agrandissement en cours.
  • upscaler_exporter · BinksyAPI.exporter() — Exporte sans téléchargement forcé le résultat agrandi (avec les retouches) en PNG, JPEG ou WebP, dpi inscrits : image courante, une image (id) ou toutes les images agrandies en ZIP (scope: all).
  • upscaler_selectionner_image · BinksyAPI.selectionnerImage() — Rend une image importée courante (comme un clic dans la liste).
  • upscaler_retirer_image · BinksyAPI.retirerImage() — Retire une image de la liste.
  • upscaler_reset · BinksyAPI.reset() — Retire toutes les images et leurs résultats (comme « Tout retirer »).

02Connexion A — agent dans le navigateur (WebMCP)

WebMCP est une proposition du W3C encore expérimentale : un agent intégré au navigateur appelle directement les outils d’une page. Pour l’essayer aujourd’hui (les noms peuvent encore changer d’une version à l’autre) :

  1. Utilise un Chrome récent (146 ou plus, souvent Canary ou Dev) et ouvre chrome://flags/#enable-webmcp-testing, passe le réglage WebMCP for testing sur Enabled, puis relance Chrome.
  2. Ouvre https://upscaler.binksdesign.com/app.html (ou http://localhost…/app.html en local : il faut HTTPS ou localhost).
  3. Les outils upscaler_… apparaissent tout seuls pour l’agent du navigateur. Pour les voir et les tester à la main, l’extension Chrome Model Context Tool Inspector (proposée par la doc Chrome) les liste et les exécute.

L’app gère document.modelContext.registerTool() (spécification actuelle) et les anciennes préversions (navigator.modelContext, provideContext). Sans WebMCP, rien ne s’affiche et rien ne casse : window.BinksyAPI reste disponible.

03Connexion B — Claude Code, Codex, Hermes, OpenCode

Ces agents pilotent un navigateur local par un serveur MCP standard. Le plus simple : Playwright MCP. Ajoute-le à la configuration MCP de ton agent (fichier .mcp.json de Claude Code, configuration MCP de Codex, Hermes ou OpenCode — même bloc, la syntaxe du fichier peut varier) :

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

Puis demande à l’agent d’ouvrir l’app (browser_navigate vers https://upscaler.binksdesign.com/app.html) et d’appeler window.BinksyAPI avec l’outil d’évaluation de JavaScript (browser_evaluate), par exemple :

() => BinksyAPI.describe()

Pour un fichier de l’utilisateur, l’agent le lit sur le disque, l’encode en base64 et le passe à BinksyAPI.importer({ files: [{ name, type, dataBase64 }] }). Les fichiers exportés reviennent en base64 : l’agent les réécrit sur le disque. Respecte les licences : 5 modèles sont non commerciaux (champ commercialUse de listerModeles). N’agrandis que les images de l’utilisateur et ne présente jamais un agrandissement comme un vectoriel.

04Exemples de code

Découvrir l’app et les modèles

await BinksyAPI.ready();
const info = await BinksyAPI.describe();
const { models } = await BinksyAPI.listerModeles();   // id, licence, commercialUse, poids, usage conseillé
const etat = await BinksyAPI.getState();             // images, réglages, moteur IA prêt ou non

Importer une image en base64 et agrandir

await BinksyAPI.importer({ files: [{ name: 'logo.png', type: 'image/png', dataBase64: b64 }] });
await BinksyAPI.choisirModele({ id: 'anime' });   // aplats, logos ; 'clear' pour une photo
await BinksyAPI.regler({ factor: 4 });             // ou { width: 3000 }
const { result } = await BinksyAPI.agrandir({});   // { model, factor, width, height, seconds }

Exporter (rien n’est téléchargé sauf download: true)

const { files } = await BinksyAPI.exporter({ format: 'png', dpi: 300 });   // scope: 'all' = ZIP de toutes les images agrandies
files[0].name;   // logo_x4_anime.png  (+ width, height, dataBase64)

05Prompt prêt à copier

À coller tel quel dans Claude Code, Codex, Hermes ou OpenCode (avec Playwright MCP branché) :

Ouvre https://upscaler.binksdesign.com/app.html avec le navigateur (Playwright MCP, fenêtre d’au moins 900 px de large), attends que la page soit chargée, puis utilise uniquement window.BinksyAPI via browser_evaluate. Commence par await BinksyAPI.describe(). Importe mon image ./logo.png (lis-la sur le disque, encode-la en base64, BinksyAPI.importer). Choisis un modèle utilisable commercialement adapté (listerModeles, champ commercialUse), agrandis ×4 (BinksyAPI.agrandir, ça peut prendre plusieurs minutes), puis exporte en PNG 300 dpi (BinksyAPI.exporter), décode le base64 et enregistre le fichier à côté de l’original. Donne-moi la taille finale telle que l’API la renvoie. N’invente ni ne redessine rien.

06Rien n’est envoyé

  • Tes images ne sont jamais envoyées : le calcul se fait dans le navigateur. Seuls le moteur ONNX Runtime Web (jsDelivr) et les modèles (Hugging Face) sont téléchargés, comme dans l’interface ; l’API n’ajoute aucune requête. Les réglages, les images importées et leur dernier résultat agrandi sont gardés dans le navigateur (localStorage et IndexedDB, rien n’est envoyé) et reviennent au rechargement.
  • Pas de compte, pas de clé API : l’API ne lit ni n’écrit aucune clé.
  • L’API manipule seulement ce que l’utilisateur fournit : elle n’invente ni logo, ni couleur, ni nom de client.

English, short version. Upscaler exposes one tool table two ways: the always-present window.BinksyAPI object in app.html and, when the browser supports it, auto-registered WebMCP tools. Every call runs the same logic as the UI (screen and auto-save follow), returns JSON and rejects with { code, message }.

02Connecting an agent

  • WebMCP (browser agent): recent Chrome (146+), enable chrome://flags/#enable-webmcp-testing, relaunch, open https://upscaler.binksdesign.com/app.html; the upscaler_… tools show up automatically (inspect them with the Model Context Tool Inspector extension). Experimental: names may change.
  • Claude Code, Codex, Hermes, OpenCode: add Playwright MCP (npx @playwright/mcp@latest, config block above), open the app URL, then call window.BinksyAPI through browser_evaluate. Files go in and out as base64.
  • Images are never uploaded: processing happens in the browser. Only the ONNX Runtime Web engine (jsDelivr) and the models (Hugging Face) are downloaded, as in the UI; the API adds no request. Settings, imported images and their latest upscaled result are kept in the browser (localStorage and IndexedDB, nothing is uploaded) and come back after a reload. No account, no API key.

03Ready-to-paste prompt

Open https://upscaler.binksdesign.com/app.html in the browser (Playwright MCP, window at least 900 px wide), wait for the page to load, then use only window.BinksyAPI through browser_evaluate. Start with await BinksyAPI.describe(). Import my image ./logo.png (read it from disk, base64-encode it, BinksyAPI.importer). Pick a suitable commercially usable model (listerModeles, commercialUse field), upscale ×4 (BinksyAPI.agrandir, may take minutes), export as 300 dpi PNG (BinksyAPI.exporter), decode the base64 and save the file next to the original. Report the final size exactly as the API returns it. Do not invent or redraw anything.
